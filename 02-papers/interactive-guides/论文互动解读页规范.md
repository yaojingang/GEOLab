# 论文互动课堂规范（PGS v2.0）

PGS = Paper Guide Spec。本规范定义如何把 `02-papers/` 中的一篇论文，做成一门约 20 页的**互动白板课**：左侧是两级知识目录，右侧是一页一页的 16:9 宽屏白板，每页讲一个主题，把原理、演示、交互、方法和应用融进去。

- **标准样例**：[`01_GEO基础框架_GEO_Generative_Engine_Optimization.html`](./01_GEO基础框架_GEO_Generative_Engine_Optimization.html)（7 章 23 页）
- **适用对象**：负责批量生成课程的 AI 与人工审校者
- **一条原则**：样例就是模板。外壳 CSS 与 core runtime 照抄，只替换页面内容与数据；遇到本文没写到的情况，以样例的做法为准。

| 版本 | 形态 | 状态 |
| --- | --- | --- |
| v1.0 | 单页长滚动解读 | 已被 v2.0 取代 |
| v2.0 | 两级目录 + 分页白板课堂 | 当前版本 |

## 1. 目标与质量标准

一门课要让三类学习者各有所得：

| 学习者 | 学完封面和前 3 页 | 学完全部约 20 页 |
| --- | --- | --- |
| 业务读者（运营、市场、管理者） | 知道论文解决什么问题、结论是什么 | 拿到可执行的行动清单 |
| 从业者（GEO / SEO / 内容） | 知道哪些方法有效、效果多大 | 理解指标、实验设置与适用边界 |
| 研究者 | 定位贡献与证据强度 | 看到公式、完整数据、局限与后续研究对照 |

合格标准：

1. **一页一个主题**：每页标题是一句完整的判断，读者只看标题也能串起整篇论文。
2. **讲得懂**：通俗层不出现未解释的术语；每个专业词都可点开解释。
3. **动得了**：全课至少 10 个交互，每个回答一个具体问题，打开就有信息量。
4. **信得过**：每个论文数字都能在 `PAPER` 数据对象里找到，并标注出处。
5. **用得上**：有论文原例拆解、分角色行动清单、成熟内容形态对照。
6. **装得下**：每页内容在 1160×652 的白板内放下，`PGS.checkAll()` 返回空数组。
7. **看得舒服**：纯白背景，无渐变，克制的颜色，出版物级排版。

## 3. 生产流程

```
① 取文 → ② 精读抽取（Paper Brief） → ③ 课程编排（Syllabus） → ④ 写作 → ⑤ 实现 → ⑥ 自检
```

### ① 取文

- 从 `00_资料说明/论文清单.csv` 读取分类、文件名、题名、年份、来源、URL。
- 本地有 PDF 时用 `pdftotext -layout`（表格）和 `pdftotext`（正文）各抽一份。
- `本地阅读_2026-10-25/` 中的论文没有再分发许可：课程只链接原站，不链接本地 PDF。

### ② 精读抽取：Paper Brief

先写 Brief，再写课程。Brief 不进入页面，但决定全部内容：

```yaml
meta:
  title_zh: 中文题名（意译，12 字以内为佳）
  title_en: 原题名
  authors: 第一作者等 N 人
  venue: 会议/期刊 + 年份；arXiv 编号与版本号
  category: 所属分类目录，例如 01 GEO 基础框架
  links: {arxiv: , doi: , code: , local_pdf: 相对路径或空}
one_liner: 一句话结论，40–70 字，包含最关键的一个数字
learning_goals: [学完能回答的 4 个问题]
stakeholders_or_motivation: 论文要解决的痛点，谁受益谁受损
system_or_pipeline: 论文研究的系统流程，拆成 3–6 步，标出论文干预的环节
metrics: [{name, plain, formula, source}]
experiment: {data, scale, model, baseline, repeats, external_validation}
methods: [{id, zh, en, plain, pro, needs_new_content, source}]
results:
  - table: Table 1
    columns: [...]
    rows: {method_id: [...]}
findings:            # 4–6 条
  - {id: F1, headline, evidence: "Table 1 · §4", strength: 强|中|弱, why_strength}
quotes: [{zh, src, more, use}]           # 6 条
paper_cases: [{method, uplift, query, before, after}]
personas: [{role, scene, why, todo[3–5], avoid}]
mature_examples: [{form, example, features, mapped_methods}]
limitations: [{severity: 高|中|低, title, body, related_paper}]   # 4–7 条
discrepancies: [正文、图注、表格之间不一致的地方]
glossary: [{key, term, def}]              # 6–12 个
quiz: [{q, options[4], answer, explain, review_page}]   # 5 题
```

抽取规则：

- 表格数字逐格核对两遍：`-layout` 版本按行读，原始版本按列读，两者一致才写入。
- 论文正文的百分比与按表格均值换算的百分比不一致时，两个都记下，写入 `discrepancies`。
- 证据强度判定：

| 强度 | 判定条件 |
| --- | --- |
| 强 | 主实验与至少一个额外设置（另一引擎、另一数据集、人工评估）结论一致，样本 ≥ 500 |
| 中 | 只在一个设置下观察到，或依赖自动标注，或样本 100–500 |
| 弱 | 样本 < 100、作者自述为初步结果，或论文内部表述存在冲突 |

### ③ 课程编排：Syllabus

| --- | --- | --- | --- | --- | --- | --- | --- |

## 4. 课程结构

### 4.1 章与页

- 全课 **18–24 页**，分 **6–8 章**，每章 2–5 页。
- 侧栏两级：**章**（编号 + 名称 + 页数）→ **页**（页码 + 短标题 + 已学标记）。
- 标准章节骨架如下。章名可以按论文调整，顺序保持“问题 → 原理 → 测量 → 方法 → 发现 → 应用 → 复盘”。

| 章 | 名称 | 页数 | 必备页 | 作用 |
| --- | --- | --- | --- | --- |
| 1 | 导入 | 3 | 课程封面、学习路线、问题场景 | 让学习者感到问题存在 |
| 2 | 原理 | 2–3 | 动机 / 利益方、系统流程、核心概念 | 建立理解论文所需的模型 |
| 3 | 测量 | 2–3 | 指标、实验设计 | 讲清“怎么判断有效” |
| 4 | 方法 | 2–3 | 方法总览、方法细看、效果对比 | 论文做了什么 |
| 5 | 发现 | 3–5 | 每页一条关键发现 | 实验说明了什么，可信度多高 |
| 6 | 应用 | 2–3 | 论文原例、角色行动清单、成熟形态对照 | 怎么用 |
| 7 | 复盘 | 3 | 批判性阅读、金句总结、自测 | 边界、带走什么、是否学会 |

论文类型不同时的调整：

- **综述 / 理论框架类**：第 3 章改为“框架拆解”，第 4 章改为“流派对比”，第 5 章每页讲一个共识或分歧。
- **实证测量类**：第 3 章扩到 3 页，突出口径、样本与平台差异。
- **攻击 / 风险类**：第 4 章改为“攻击如何发生”（步进器演示），第 6 章的行动清单改为防御清单，并在应用章加底线提示页。
- **系统 / 方法类（RAG、Agentic Search）**：第 2 章必含系统流程步进器，第 5 章用消融实验切换展示各模块贡献。

### 5.2 交互规则

1. **一页一个主交互**，必要时可配一个次要控件（如指标切换）。
2. **一个交互回答一个问题**，问题写进页面标题或讲解文字。
3. **默认状态就有信息量**：打开页面不操作也能读到结论。
4. **联动优于新增**：同一数据的不同视图互相跳转（样例：总览卡片 → 实验室；条形图 → 实验室）。
5. **全部可用键盘完成**：交互元素一律 `<button>`；分段控件用 `aria-pressed`；动态区域加 `aria-live="polite"`。页内组件需要方向键时要 `preventDefault()`，避免触发翻页。
6. **触屏可用**：悬停才出现的信息，点击和聚焦也要能触发。
7. **动效克制**：只用 0.25–0.5s 的淡入、宽度、位置过渡；尊重 `prefers-reduced-motion`。
8. **不依赖网络**：不加载外部字体、图表库或 CDN；图表用 HTML/CSS 绘制。

## 6. 写作规范

### 6.1 页面标题

- 写成一句完整的判断（断言），≤ 26 字。例：“可见性取决于两件事：被写了多少，写在哪里”。
- 避免目录式标题，如“实验结果”“方法介绍”。
- 全部页面标题连起来读，应能复述整篇论文。
- 侧栏短标题另写，≤ 10 字，名词短语即可。

### 6.2 白板文字量

- 每页正文 ≤ 120 字（不含图表、卡片内的短句和图注）。
- 每段 1–3 句，每句尽量 ≤ 40 字。
- “本页要点”一句话，≤ 50 字。
- 讲稿 2–4 句，口语化，告诉老师这一页让学生看什么、动什么、记住什么。

### 6.3 通俗层与专业层

- **通俗层**：生活化类比和具体场景，零公式；专业词首次出现时做成术语按钮。
- **专业层**：公式、实验设置、完整表格、术语原文；用 `.pro-note`、`.only-pro` 或在交互中切换文本（如步进器、实验室的 `pro` 字段）。
- 两层文字长度相近，切换后同样不能溢出白板。

### 6.4 禁用句式与用词

- 禁用“先否定一个说法、再转向另一个说法”的句式，包括 `不是……而是……`、`并非……而是……`、`不只是……而是……` 及同类变体。需要对比时，用并列事实、递进、条件或范围说明。
  - 改前：GEO 不是改排名，而是改内容。
  - 改后：GEO 作用于网页内容，不改变搜索排名。
- 禁用空泛词：赋能、抓手、闭环、颠覆、革命性、重磅、震撼。
- 不使用 emoji。
- 数字与中文之间加半角空格：`约 40%`、`10,000 条`；提升写作 `+27.5%` / `−8.3%`（负号用 U+2212）。

### 6.5 数字与出处

- 每个论文数字都来自 `PAPER` 数据对象，并在附近标注出处：`<span class="src">Table 1</span>`，或写在图注、本页要点中。
- 派生数字（如由均值换算的相对提升）在图注中写明换算方式。
- 论文内部不一致时，在相关页面图注和批判性阅读页各说明一次，写明“以表格数值为准”。
- 不改变含义地取整：论文写 41% 就写 41%。

### 6.6 示意内容

为演示编写的文本、网站、人名、数字、引语必须：

1. 在图注或本页要点中写明“示意”“演示虚构”；
2. 编造的机构用“某××”命名，不使用真实机构名；
3. 不出现可被误读为真实统计的精确数字，除非紧邻“示意”字样。

### 6.7 发现页

每条发现单独一页（或两条对照放一页），页面上必须有：发现编号（F1…）、证据出处、证据强度（强 / 中 / 弱，按第 3 节判定）、一个可视化或交互。

### 6.8 应用章

三类内容缺一不可：

1. **论文原例拆解**：使用论文自带的定性例子，中文转述，写清查询、原句、改动、提升幅度。论文没有定性例子时，用方法描述构造示意例子并标注。
2. **角色行动清单**：2–4 个角色，每个写“为什么适合 / 可以这样做（3–5 条，动词开头）/ 避免”，每条建议能追溯到某条发现。
3. **成熟内容形态对照**：3–6 类公认的成熟内容形态或真实产品，写写法特征与对应策略，并注明“这一对应关系是本页的推断”。

风险类论文的应用章必须包含底线提示（`.callout.warn`）。

### 6.9 复盘章

- **批判性阅读页**：4–7 条，按影响分高 / 中 / 低；至少覆盖实验环境差距、评估偏差、样本或场景局限、内部不一致、仓库内后续研究对照中的 3 个角度。引用仓库内其他论文时链接本地 PDF，只引用其摘要中明确写出的结论。
- **金句页**：6 条，每条中文 12–30 字，可脱离上下文成立；卡片背面写论文依据和一个具体用法；复制时附出处。
- **自测页**：5 道单选，覆盖核心结论、反常发现、指标理解、适用边界、局限；每题解释写明复习页码。

## 7. UI 规范

### 7.1 设计原则

- **纯白背景**：页面、白板、卡片背景均为 `#ffffff`。只有提示块、轨道底色、代码块可用 `--tint` 等平涂浅色。
- **无渐变**：禁止 `linear-gradient`、`radial-gradient`、渐变文字、彩色光晕、背景网格图案。
- **无装饰阴影**：只有浮层与右侧抽屉允许一层轻阴影。
- **颜色只承载信息**：黑色是主色；蓝色表示交互、当前位置与强调；绿 / 红只表示正向 / 负向；橙色只作为图表第二系列。
- **衬线标题 + 无衬线正文**：页面标题、关键数字、金句用衬线体。

## 8. 技术规范

### 8.1 文件

- 位置：`02-papers/interactive-guides/`
- 文件名：与论文 PDF 同名，扩展名改为 `.html`。无本地 PDF 的论文，用 `分类前缀_英文短名.html`。
- 单文件、零外部依赖；体积 ≤ 200 KB。
- `<title>`：2–4 个词的中文名称（如“GEO 论文课堂”）；`<meta name="description">` 一句话；`<meta name="paper-guide-spec" content="PGS v2.0">`；`<meta name="paper-guide-source" content="arXiv:xxxx.xxxxxvN">`。
- 链接：论文导航 `../index.html`；本地 PDF 与仓库内相关论文用相对路径；外链加 `target="_blank" rel="noopener"`。

### 8.2 代码结构

```
<style>
  PGS core v2.0          ← 原样复制（外壳、白板、通用组件、移动端）
  本课程专用组件          ← 按需保留、删减或新增
</style>
<body class="mode-plain">
  aside.side             ← 原样复制（目录由 runtime 生成）
  .main > .bar-top / .stage / .notes-panel / .bar-bot   ← 原样复制
    .stage 内：section.page × 18–24   ← PAPER CONTENT，按本篇重写
  .drawer                ← 替换 BibTeX 与来源
<script>
  const CHAPTERS = [...]            ← 章名与一句话说明
  const PAPER = {...}               ← 论文数字，注释写明来源表格与列顺序
  const DOCS / GLOSSARY / ... / QUIZ ← 内容数据
  PGS core runtime v2.0             ← 原样复制
  PAPER CONTENT runtime             ← 本课程的交互渲染
  启动                               ← 原样复制
</script>
```

- 数据层与表现层分离：渲染函数只读数据对象，不在 HTML 里手写论文数字。
- 依赖当前模式的渲染函数（如步进器、实验室）注册到 `MODE_HOOKS`，切换通俗 / 专业时自动重绘。
- 跳转到其他页用 `go(index)`，按页面 `data-t` 查找索引，避免写死页码。
- `localStorage` 一律经 `store` 包装；学习进度的键为 `pgs:<文件名>`。
- 不使用 `eval`；`innerHTML` 只拼接页面内常量。
