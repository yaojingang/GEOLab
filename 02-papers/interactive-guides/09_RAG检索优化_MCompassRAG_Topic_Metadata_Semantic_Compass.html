怎样让大块文档兼顾检索速度和证据精度

粗块省时延，但单一向量会被块内无关内容带偏§1 · PDF p.1-2
用长手册的场景引入粒度取舍：块小了候选多、时延高，块大了向量糊。先让学生选“常见做法”看单向量的问题，再切到“研究启发”看论文的思路。这两段是教学构造，论文数字在后面几页。

块越大越省，但混入的主题会稀释向量

块级主题分布与同空间主题质心，构成可用的主题信号§3.1-3.2 · PDF p.3-4
讲两个核心对象：块的主题分布和主题质心。质心必须和检索器落在同一嵌入空间，这是全篇的前提。让学生点三个步骤按钮，对照右侧四个指标，先混个眼熟。

先建主题库，再蒸馏，最后主题引导检索

离线建库与蒸馏，在线只做选择、抽象与 MLP 打分§3.4 · PDF p.5
流程三步走：离线建主题库、蒸馏轻量检索器、在线主题引导检索。强调前两步都是离线一次性的，在线没有 LLM 调用，这是它时延低的原因。专业模式里有训练损失的设计细节。

改动只在检索环节，索引与生成器不动

定位干预环节，才能决定对照实验要控制什么§3 · PDF p.3
这页定位干预环节：改的只是检索的打分方式，候选空间、索引和生成器都没动。顺带说明它与查询扩展、重排等方法正交，可以叠加使用。这决定了后面实验要看什么对照。

信息效率 = 查准 × 查全，缺一不可

IE@k = Precision@k × Recall@k，k∈{1,3,5} 取平均§4.1 · PDF p.6
指标页先纠一个直觉：IE 是查准乘查全，两个因子缺一个就归零，乘积在 k=1、3、5 上取平均。让学生切专业模式看公式，再对照右侧的检查次序。时延和 token 是代价侧的口径。

六个基准、固定 1K 证据预算下对照

证据按排名补齐到同一预算，块粒度不同的方法才可比§4.1 · PDF p.6
实验设计页讲口径：六个基准、1K token 证据预算、三次运行取均值，块粒度不同的方法按排名补齐到同一预算。右侧可以翻五段原文节选，从摘要一直翻到定性案例。

复验先钉住口径，再谈迁移

四项检查覆盖预算、基线、超参与代价记录本课推断 · 口径见 §4.1
这是复验检查表，让学生按四项逐条勾选：预算、基线档位、超参记录、代价报告。强调这是本课推断的检查法，论文没有提供现成清单。

三个模块各司其职：缓存、蒸馏、打分

去掉选择或抽象都掉分，两者全去掉掉得最多Table 3 · PDF p.9
方法拆解页按步骤点开：元数据库是缓存，蒸馏解决“教师看扩展查询、学生只看基础查询”的信息不对称，MLP 打分器负责最后排序。关键证据是 Table 3：去掉选择或抽象都掉分，两个都去掉掉得最多。

IE 领先与低时延可以同时成立

六基准 IE 全部高于最强高效基线，时延 174 ms 居高效档Table 1/2 · PDF p.7-8

粗块把上下文和时延一起省下来

每查询 4,126 token、174 ms，低于高效基线Table 2 · PDF p.8
发现一：粗块省的是上下文和时延。数字在 Table 2：每查询 4,126 token、端到端 174 毫秒，对比 SAKI-RAG 的 5,584 token、925 毫秒。代价是块内混主题，引出下一页的问题。

共享措辞会让余弦相似度排错定义

C2 以 0.81 压过金块 C3 的 0.78，排到第 1Figure 4 · PDF p.22
发现二：块里混多个主题，单向量被稀释。Figure 4 里两个定义条款共享 bona fide、majority 这些词，余弦把错误定义排到了第 1。这是粗块检索最典型的失败模式，第 11 页可以亲手重演。

主题元数据把证据选择的精度补回来

六基准 IE 全部高于最强非 LLM 基线Table 1 · PDF p.7
发现三：主题元数据改善证据选择，六基准 IE 全部高于最强非 LLM 基线，这是 Table 1 的主结论。多跳基准 DRBench 上差距最大：47.97 对 37.47。让学生点“实践含义”看怎么落地。

在线检索不调用 LLM，质量接近神谕

与 LLM 神谕 IE 差距：SCI-DOCS 0.54 点、SQuAD 0.30 点§4.2 · PDF p.7
发现四：在线不调 LLM 也接近神谕上界。SCI-DOCS 差 0.54 点、SQuAD 差 0.30 点，其余基准差 2 到 3 点。代价转移到离线训练，多轮检索场景里这笔账更划算。

对照 SproutRAG：干预环节不同

一篇补块表示，一篇组织分块树，指标不可直接相加§2 · PDF p.2
